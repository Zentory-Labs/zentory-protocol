# GOV-002: veBalance Decay Implementation Decision

**Date:** 2026-08-20
**Status:** DECIDED
**Decision maker:** Founder (Edge)

## Context

`ZENTStaking.sol` has a critical bug (Tier 0 Q1): `totalVeSupply` ratchets up forever while individual `veBalance()` decays to 0. This causes `ZentGovernor.quorum = totalVeSupply * quorumBps / 10000` to become permanently unreachable, bricking governance.

The root cause: `withdraw()` requires `block.timestamp >= pos.lockEnd`, but `_veAt()` returns 0 once `at >= lockEnd`. So `totalVeSupply -= oldVe` always subtracts zero.

## Options Considered

### Option A: Curve-style checkpointed slope decay

Reference: Curve Finance's `VotingEscrow.vy` — `_checkpoint` pattern with historical lookup.

**Implementation:**
- Add `Checkpoints.History` storage (`_veCheckpoints[address]`) with `_writeCheckpoint/_getCheckpointAtBlock` helpers from OpenZeppelin
- Rewrite `_veAt()` to read from the checkpoint history at the requested timestamp
- Rewrite `withdraw()` to subtract the user's historical ve at withdraw-time
- Add `getPriorVeBalance(address, uint256)` public view for governor snapshots

**Pros:**
- Matches the battle-tested Curve/Convex implementation
- Governor snapshots become trivially correct (Q7 sub-fix is implicit)
- Every external user can verify their own veBalance decay via the public getter

**Cons:**
- ~150–250 LOC change + storage restructure
- Existing testnet stakers lose historical ve at first withdraw post-upgrade (one-time migration required)
- ZENTStaking storage layout currently fully packed; append-only storage needed

### Option B: Base quorum on `totalStaked` instead of `totalVeSupply`

**Implementation:**
- Change `ZentGovernor.quorum = totalStaked * quorumBps / 10000`
- `totalStaked` is already maintained correctly (incremented at stake, decremented at withdraw)

**Pros:**
- Very small change (~10 LOC)
- No storage migration needed
- Governance works immediately

**Cons:**
- Changes governance semantics (quorum is based on raw stake, not time-weighted stake)
- Does not fix the veBalance decay display issue for individual users
- Removes the time-decay incentive for governance participation
- External tools reading `totalVeSupply` will see incorrect values indefinitely

## Decision

**Chosen: Option A — Curve-style checkpointed slope decay.**

Rationale:
1. Time-weighted governance is a core protocol design choice — `totalStaked`-based quorum defeats the purpose of vote-escrow
2. Q7 (governor snapshots) is implicitly fixed by this approach
3. The one-time migration is acceptable at this pre-mainnet stage
4. The Curve implementation is the industry standard and has been audited extensively

## Migration Plan

- Existing testnet stakers will lose historical ve at the first withdraw post-upgrade
- A `script/MigrateVeHistory.s.sol` will snapshot every active position at the upgrade block
- This is a one-time cost paid in testnet; mainnet will deploy with the fix from genesis
